# 事件溯源架构流程文档

## 1. 事件溯源概述

事件溯源（Event Sourcing）是本系统的核心架构模式，通过记录所有状态变更事件来重建聚合根状态，确保数据的完整性和可追溯性。

## 2. 事件溯源核心组件

### 2.1 核心类图

```mermaid
classDiagram
    class EventSourcedAggregateRoot {
        -uncommittedEvents: List~DomainEvent~
        -lastEventVersion: Long
        +recordEvent(event: DomainEvent)
        +replayEvents(events: List~DomainEvent~)
        +getUncommittedEvents(): List~DomainEvent~
        +markEventsAsCommitted()
        +createSnapshot(): AggregateSnapshot
        +restoreFromSnapshot(snapshot: AggregateSnapshot)
    }
    
    class EventStore {
        +saveEvents(aggregateId: String, events: List~DomainEvent~, expectedVersion: Long)
        +getEvents(aggregateId: String, fromVersion: Long): List~DomainEvent~
        +getCurrentVersion(aggregateId: String): Long
        +saveSnapshot(snapshot: AggregateSnapshot)
        +getLatestSnapshot(aggregateId: String): AggregateSnapshot
    }
    
    class SnapshotService {
        +createSnapshot(aggregate: EventSourcedAggregateRoot)
        +getLatestSnapshot(aggregateId: String): AggregateSnapshot
        +cleanupOldSnapshots(aggregateId: String)
        +getSnapshotStats(aggregateId: String): SnapshotStats
    }
    
    class ConcurrencyException {
        +aggregateId: String
        +expectedVersion: Long
        +actualVersion: Long
    }
    
    EventSourcedAggregateRoot --> EventStore
    EventSourcedAggregateRoot --> SnapshotService
    EventStore --> ConcurrencyException
```

### 2.2 组件职责

- **EventSourcedAggregateRoot**: 事件溯源聚合根基类，管理未提交事件和状态重建
- **EventStore**: 事件存储接口，负责事件持久化和检索
- **SnapshotService**: 快照服务，优化事件重放性能
- **ConcurrencyException**: 并发冲突异常，处理版本冲突

## 3. 事件溯源业务流程

### 3.1 聚合根创建流程

```mermaid
sequenceDiagram
    participant Client
    participant Service
    participant Aggregate
    participant EventStore
    participant EventBus
    
    Client->>Service: 创建聚合根命令
    Service->>Aggregate: 创建新聚合根实例
    Aggregate->>Aggregate: recordEvent(CreatedEvent)
    Service->>EventStore: saveEvents(aggregateId, events, 0)
    EventStore->>EventStore: 检查版本冲突
    EventStore->>EventStore: 持久化事件
    EventStore-->>Service: 保存成功
    Service->>Aggregate: markEventsAsCommitted()
    Service->>EventBus: 发布领域事件
    Service-->>Client: 返回结果
```

### 3.2 聚合根更新流程

```mermaid
sequenceDiagram
    participant Client
    participant Service
    participant Repository
    participant Aggregate
    participant EventStore
    participant SnapshotService
    
    Client->>Service: 更新聚合根命令
    Service->>Repository: load(aggregateId)
    Repository->>SnapshotService: getLatestSnapshot(aggregateId)
    SnapshotService-->>Repository: 返回快照(可选)
    Repository->>EventStore: getEvents(aggregateId, fromVersion)
    EventStore-->>Repository: 返回事件列表
    Repository->>Aggregate: 创建聚合根实例
    alt 存在快照
        Repository->>Aggregate: restoreFromSnapshot(snapshot)
    end
    Repository->>Aggregate: replayEvents(events)
    Repository-->>Service: 返回聚合根
    Service->>Aggregate: 执行业务操作
    Aggregate->>Aggregate: recordEvent(UpdatedEvent)
    Service->>Repository: save(aggregate)
    Repository->>EventStore: saveEvents(aggregateId, events, expectedVersion)
    EventStore->>EventStore: 检查版本冲突
    EventStore->>EventStore: 持久化事件
    Repository->>Aggregate: markEventsAsCommitted()
    Service-->>Client: 返回结果
```

### 3.3 并发冲突处理流程

```mermaid
sequenceDiagram
    participant Service
    participant Repository
    participant EventStore
    participant Aggregate
    
    Service->>Repository: save(aggregate)
    Repository->>EventStore: saveEvents(aggregateId, events, expectedVersion)
    EventStore->>EventStore: getCurrentVersion(aggregateId)
    EventStore->>EventStore: 比较版本号
    alt 版本冲突
        EventStore-->>Repository: throw ConcurrencyException
        Repository->>Repository: 重试逻辑开始
        Repository->>Repository: 延迟等待
        Repository->>Repository: 重新加载聚合根
        Repository->>Aggregate: 重新应用业务逻辑
        Repository->>EventStore: 重新尝试保存
        alt 重试成功
            EventStore-->>Repository: 保存成功
        else 重试失败
            Repository-->>Service: throw ConcurrencyException
        end
    else 版本正常
        EventStore->>EventStore: 保存事件
        EventStore-->>Repository: 保存成功
    end
```

## 4. 快照管理流程

### 4.1 快照创建流程

```mermaid
sequenceDiagram
    participant Repository
    participant Aggregate
    participant SnapshotService
    participant EventStore
    
    Repository->>Aggregate: 检查是否需要创建快照
    alt 满足快照条件
        Repository->>SnapshotService: createSnapshot(aggregate)
        SnapshotService->>Aggregate: createSnapshot()
        Aggregate->>Aggregate: serializeState()
        Aggregate-->>SnapshotService: 返回快照数据
        SnapshotService->>EventStore: saveSnapshot(snapshot)
        EventStore-->>SnapshotService: 保存成功
        SnapshotService->>SnapshotService: 记录快照统计
    end
```

### 4.2 快照清理流程

```mermaid
sequenceDiagram
    participant Scheduler
    participant SnapshotService
    participant EventStore
    
    Scheduler->>SnapshotService: 定时清理任务
    SnapshotService->>EventStore: 查询过期快照
    EventStore-->>SnapshotService: 返回快照列表
    SnapshotService->>EventStore: 删除过期快照
    SnapshotService->>SnapshotService: 更新统计信息
    SnapshotService-->>Scheduler: 清理完成
```

## 5. 事件重放流程

### 5.1 完整重放流程

```mermaid
sequenceDiagram
    participant EventReplayService
    participant EventStore
    participant SnapshotService
    participant Aggregate
    
    EventReplayService->>SnapshotService: getLatestSnapshot(aggregateId)
    SnapshotService-->>EventReplayService: 返回快照(可选)
    alt 存在快照
        EventReplayService->>EventStore: getEvents(aggregateId, snapshot.version + 1)
        EventReplayService->>Aggregate: restoreFromSnapshot(snapshot)
    else 无快照
        EventReplayService->>EventStore: getEvents(aggregateId, 0)
    end
    EventStore-->>EventReplayService: 返回事件列表
    EventReplayService->>Aggregate: replayEvents(events)
    EventReplayService-->>EventReplayService: 返回重建的聚合根
```

## 6. 性能优化策略

### 6.1 快照策略

- **事件数量阈值**: 每100个事件自动创建快照
- **时间阈值**: 24小时强制创建快照
- **快照保留**: 保留最近10个快照
- **清理策略**: 定期清理过期快照

### 6.2 事件存储优化

- **批量保存**: 支持批量保存多个事件
- **索引优化**: 在aggregateId和version字段上建立索引
- **分区策略**: 按聚合根类型或时间分区
- **压缩存储**: 对历史事件进行压缩存储

### 6.3 并发控制优化

- **乐观锁**: 使用版本号进行乐观锁控制
- **重试机制**: 指数退避重试策略
- **最大重试次数**: 限制重试次数防止无限重试
- **冲突监控**: 监控并发冲突频率和重试成功率

## 7. 监控和运维

### 7.1 关键指标

- **事件存储性能**: 事件保存和查询延迟
- **快照效率**: 快照创建频率和恢复时间
- **并发冲突率**: 版本冲突频率和重试成功率
- **聚合根大小**: 事件数量和快照大小

### 7.2 告警策略

- **高并发冲突**: 冲突率超过5%时告警
- **快照失败**: 快照创建失败时告警
- **事件存储异常**: 事件保存失败时告警
- **性能降级**: 事件重放时间超过阈值时告警

## 8. 最佳实践

### 8.1 事件设计原则

- **事件不可变**: 事件一旦创建不可修改
- **事件完整性**: 事件包含重建状态所需的所有信息
- **事件版本化**: 支持事件结构的演进
- **事件幂等性**: 重复应用事件不会产生副作用

### 8.2 聚合根设计原则

- **单一职责**: 每个聚合根负责一个业务概念
- **事务边界**: 聚合根是事务的边界
- **状态一致性**: 通过事件确保状态一致性
- **快照支持**: 实现快照创建和恢复方法

### 8.3 性能优化建议

- **合理使用快照**: 根据聚合根大小和访问频率调整快照策略
- **事件分页**: 大量事件时使用分页加载
- **异步处理**: 事件发布和处理使用异步模式
- **缓存策略**: 对频繁访问的聚合根使用缓存
