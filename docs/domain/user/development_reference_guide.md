# 用户域开发参考指南

## 文档概述

本指南明确了用户域各PlantUML文档的用途和开发时的参考优先级，帮助开发团队高效地使用领域设计文档。

## 文档说明

### 1. user_aggregate_detail.puml（核心聚合设计）
**用途**: 详细的聚合根设计，包含完整的实体、值对象、业务方法和领域事件定义
**开发参考**: ⭐⭐⭐⭐⭐ 最高优先级
**适用场景**: 
- 实现聚合根和实体类
- 编写业务逻辑和领域方法
- 定义值对象和领域事件
- 理解聚合内部结构和约束

### 2. user_domain_cqrs.puml（CQRS架构模型）
**用途**: CQRS架构设计，包含命令、查询、处理器、DTO和事件定义
**开发参考**: ⭐⭐⭐⭐ 高优先级
**适用场景**:
- 实现命令和查询处理器
- 设计应用服务层
- 定义DTO和数据传输对象
- 构建读写分离架构

### 3. user_domain_event_flow.puml（业务流程图）
**用途**: 业务流程和事件处理流程的动态描述
**开发参考**: ⭐⭐⭐ 中等优先级
**适用场景**:
- 理解业务流程逻辑
- 实现事件处理流程
- 设计异步处理机制
- 跨域集成和事件投影

### 4. user_domain_tactical_model.puml（战术设计概览）
**用途**: 整体战术设计概览，展示领域模型的全貌
**开发参考**: ⭐⭐ 参考优先级
**适用场景**:
- 理解整体架构设计
- 新团队成员学习
- 架构评审和讨论
- 与其他域的集成设计

## 开发建议

### 推荐的开发流程

1. **首先参考** `user_aggregate_detail.puml`
   - 实现核心聚合根 `User`
   - 创建值对象 `UserId`、`Email`、`Password` 等
   - 实现业务方法和领域逻辑

2. **然后参考** `user_domain_cqrs.puml`
   - 实现命令处理器
   - 创建查询处理器
   - 设计DTO和数据传输层

3. **配合参考** `user_domain_event_flow.puml`
   - 实现事件处理流程
   - 设计异步处理机制
   - 构建事件投影

4. **整体参考** `user_domain_tactical_model.puml`
   - 验证架构一致性
   - 确保模块间集成正确

### 关键设计原则

1. **用户ID格式**: 使用自增ID字符串格式（如 USER_000001），而非UUID
2. **事件发布**: 聚合根不存储领域事件，通过 `DomainEventPublisher` 直接发布
3. **职责分离**: 聚合根专注业务逻辑，应用服务负责事件发布和协调
4. **CQRS分离**: 严格区分命令端（写）和查询端（读）的职责

### 文档维护

- 所有文档已完成中文语义注释，提升可读性
- 设计变更时需同步更新相关文档
- 定期检查文档与代码实现的一致性

## 总结

建议开发团队以 `user_aggregate_detail.puml` 为核心参考文档，配合 `user_domain_cqrs.puml` 进行应用层开发，使用 `user_domain_event_flow.puml` 理解业务流程，通过 `user_domain_tactical_model.puml` 把握整体架构。这样的参考顺序能够确保开发效率和代码质量。
