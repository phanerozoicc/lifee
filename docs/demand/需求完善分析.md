# LifeE知识库Web应用完整需求文档

## 项目概述

**项目名称：** LifeE知识库Web应用  
**项目目标：** 构建一个集LLM对话、知识库管理、智能推荐于一体的个人知识管理系统  
**核心价值：** 通过AI技术实现知识的智能化管理、检索和推荐，提升个人学习和知识积累效率

## 1. 功能性需求

### 1.1 LLM对话模块

**核心功能：**
- **对话界面：** 提供清晰、易用的对话页面，支持流式输出和多轮对话
- **提示词管理：** 用户可以创建、编辑、保存和复用自定义提示词模板
- **对话归档：** 支持将对话内容保存为Markdown文档，并归档到指定知识库的指定目录
- **RAG增强对话：** 可选择特定知识库进行检索增强生成，提供更准确的回答
- **对话历史：** 完整的对话记录管理，包含对话内容、时间戳、使用的知识库等元信息
- **模型选择：** 支持在对话时动态选择不同的LLM模型

**详细规格：**
- 支持Markdown格式的消息渲染
- 对话内容支持代码高亮、数学公式显示
- 提供对话导出功能（PDF、Word、Markdown）
- 支持对话分享和协作

### 1.2 知识库管理模块

**核心功能：**
- **知识库创建：** 支持创建多个独立的知识库，每个知识库可配置专属的嵌入模型、重排序模型和分段参数
- **文件管理：** 支持单文件和批量文件上传，支持文件夹结构上传
- **目录树展示：** 提供直观的文件目录树界面，支持文件夹展开/折叠
- **文件详情：** 显示文件名称、路径、上传时间、文件大小、文档类型等详细信息
- **内容预览：** 支持在线查看文件内容，支持多种文档格式
- **智能搜索：** 基于向量相似度和全文检索的混合搜索功能
- **文件操作：** 支持文件覆盖更新、删除、移动、重命名等操作

**支持的文件格式：**
- 文档类：PDF、Word、PowerPoint、Excel、TXT、Markdown
- 代码类：各种编程语言源码文件
- 其他：HTML、XML、JSON、CSV等

**搜索功能规格：**
- 返回结果包含：文件名、路径、文件大小、相关内容片段、相似度评分
- 支持搜索结果高亮显示
- 提供搜索历史和搜索建议

### 1.3 智能推荐系统

**核心算法：**
- **记忆曲线推荐：** 基于艾宾浩斯遗忘曲线，智能推荐需要复习的文档
- **行为分析推荐：** 基于用户阅读历史、搜索记录、对话主题等进行个性化推荐
- **权重计算：** 文件上传时间、修改时间、访问频率等因素的综合权重计算
- **目标导向推荐：** 用户可设置学习目标，系统据此推荐相关内容

**展示方式：**
- 作为系统首页的主要内容展示
- 提供推荐理由和预计阅读时间
- 支持用户反馈（有用/无用）以优化推荐算法

### 1.4 系统配置模块

**模型配置：**
- **对话模型：** 用于LLM对话功能的大语言模型配置
- **嵌入模型：** 用于文档向量化的embedding模型配置
- **重排序模型：** 用于搜索结果重排序的rerank模型配置
- **分段模型：** 用于文档智能分段的模型配置

**配置特性：**
- 每类模型支持配置多个实例，使用时可选择
- 每类模型可设置一个默认选项
- 支持详细的模型参数配置（API密钥、端点、参数等）
- 提供模型连接测试功能

**其他配置：**
- 智能推荐系统参数配置
- 全局导入导出功能
- MCP（Model Context Protocol）服务配置和管理
- 系统主题、语言等个性化设置

## 2. 非功能性需求

### 2.1 技术架构要求

**后端技术栈：**
- **核心框架：** SpringBoot 3.x + Kotlin 1.9+
- **数据存储：** PostgreSQL（主数据库）+ Redis（缓存和会话）
- **架构模式：** 多模块单体架构，支持后续微服务演进
- **设计方法：** 领域驱动设计（DDD）+ 六边形架构
- **协议支持：** MCP（Model Context Protocol）集成

**前端技术栈：**
- **核心框架：** React 18 + TypeScript + Next.js 14
- **样式框架：** Tailwind CSS + Headless UI
- **构建工具：** Vite（开发构建优化）
- **状态管理：** Zustand + React Query

### 2.2 性能要求

- **响应时间：** 页面加载时间 < 2秒，API响应时间 < 500ms
- **并发支持：** 支持100+并发用户
- **文件处理：** 支持单文件最大100MB，批量上传总计1GB
- **搜索性能：** 千万级文档检索响应时间 < 1秒

### 2.3 安全性要求

- **身份认证：** JWT令牌认证 + Spring Security
- **数据加密：** 敏感数据加密存储，HTTPS传输
- **权限控制：** 基于角色的访问控制（RBAC）
- **数据备份：** 自动定时备份，支持增量备份
- **审计日志：** 完整的用户操作日志记录

### 2.4 可用性要求

- **系统可用性：** 99.5%以上
- **容错机制：** 优雅降级，服务熔断
- **监控告警：** 系统性能监控和异常告警
- **部署方式：** Docker容器化部署

### 2.5 扩展性要求

- **模块化设计：** 支持功能模块独立开发和部署
- **API开放：** 提供RESTful API供第三方集成
- **插件系统：** 支持功能插件扩展
- **多租户支持：** 为后续多租户架构预留接口

## 3. 现有产品对比分析

### 3.1 主流AI知识库产品特点

基于对Cherry Studio、AnythingLLM、MaxKB等产品的分析，现有AI知识库产品主要特点：

**Cherry Studio特点：**
- 多模型支持（支持30+服务商）
- 本地知识库RAG功能
- 联网搜索能力
- 智能体创建
- 文生图功能
- 零代码/低代码开发

**AnythingLLM特点：**
- 本地部署，数据安全
- 支持多种文档格式
- 自动文本分割和向量化
- 支持Ollama本地模型
- Docker容器化部署

**通用产品优势：**
- 开源免费，本地部署保证数据安全
- 支持多种大模型和文档格式
- 可视化界面，易于操作
- RAG技术实现知识库问答

### 3.2 用户需求的独特优势

对比现有产品，LifeE具有以下独特优势：

1. **智能推荐系统** - 基于记忆曲线和用户行为的文章推荐，现有产品普遍缺乏
2. **精细化知识库管理** - 支持目录树结构、文件版本管理、批量操作
3. **知识闭环设计** - 对话内容可保存为MD并归档到知识库
4. **多模型类型配置** - 对话、嵌入、重排序、分段模型分离配置
5. **MCP协议集成** - 动态扩展对话能力
6. **企业级架构** - DDD+六边形架构，支持微服务演进

## 5. 技术架构设计

### 5.1 领域驱动设计（DDD）

#### 5.1.1 领域划分
```
1. 用户域(User Domain)
   - 用户管理、认证授权、权限控制
   <!-- - 团队管理、角色分配 -->

2. 对话域(Conversation Domain)
   - LLM对话、提示词管理
   - 对话历史、会话管理

3. 知识库域(Knowledge Domain)
   - 文档管理、索引构建
   - 搜索检索、版本控制

4. 推荐域(Recommendation Domain)
   - 智能推荐、学习轨迹
   - 目标管理、进度跟踪

5. 配置域(Configuration Domain)
   - 模型配置、系统设置
   - MCP管理、插件配置
```

#### 5.1.2 技术架构层次
```
应用层(Application Layer)
├── REST API
├── WebSocket（实时功能）
├── GraphQL（复杂查询）
└── 事件处理器

领域层(Domain Layer)
├── 领域服务
├── 领域事件
├── 聚合根
└── 值对象

基础设施层(Infrastructure Layer)
├── 数据持久化
├── 外部服务集成
├── 消息队列
└── 缓存管理

接口层(Interface Layer)
├── Web UI
├── Mobile适配
├── API文档
└── 管理后台
```

## 7. 风险评估与建议

### 7.1 技术风险

**风险点：**
- 向量数据库性能瓶颈
- 大模型API调用成本
- 实时功能的并发处理

**缓解措施：**
- 采用pgvector + Elasticsearch混合架构
- 实现模型调用缓存和限流
- 使用WebSocket连接池管理

### 7.2 项目风险

**风险点：**
- 功能范围过大，开发周期延长
- 用户需求变更频繁
- 团队协作效率

**缓解措施：**
- 采用敏捷开发，分阶段交付
- 建立需求变更管理流程
- 使用协作工具提高沟通效率

### 7.3 建议

1. **MVP优先：** 先实现核心功能，再逐步扩展
2. **用户反馈：** 每个阶段都要收集用户反馈
3. **技术债务：** 定期重构，避免技术债务积累
4. **文档维护：** 保持技术文档和用户文档的及时更新
5. **安全第一：** 从设计阶段就考虑安全性

## 9. 总结

通过对比分析现有AI知识库产品，LifeE在智能推荐、知识管理精细化、企业级架构等方面具有明显优势。本需求文档涵盖了完整的功能性需求、非功能性需求、技术架构设计和开发计划。

采用分阶段开发策略，既能保证MVP的快速交付，又为后续功能扩展留下充足空间。建议优先级为：
- **P0：** 基础架构、核心对话、知识库管理
- **P1：** 智能推荐、用户管理、高级搜索
- **P2：** 知识图谱、版本控制、移动适配
- **P3：** 插件系统、API开放、高级安全特性

这样的规划既满足了核心需求，又具备了与现有产品竞争的差异化优势，为构建一个优秀的个人知识管理系统奠定了坚实基础。
